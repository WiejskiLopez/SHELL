To jest strzał w dziesiątkę! Wypięcie publishera z handlerów to ostateczny, najczystszy krok w stronę prawdziwej, asynchronicznej architektury Event-Driven.

Dzięki temu Twoje handlery komend stają się w 100% odpowiedzialne tylko za modyfikację stanu (zapisanego w bazie razem z logiem do Outboxa) i nie muszą czekać na jakiekolwiek efekty uboczne (jak budowa grafu czy wywoływanie kolejnych node'ów).

Oto jak w pełni zrealizować Twój pomysł i "odciąć" publikację z głównego wątku:

Zmieniony ImportTaskHandler (Czysty zapis):

Python
class ImportTaskHandler:
    def __init__(self, uow: UnitOfWork, clock: Clock, id_gen: IdGenerator, task_loader: TaskLoader, logger: Logger):
        self._uow = uow
        self._clock = clock
        self._id_gen = id_gen
        self._task_loader = task_loader
        self._logger = logger

    async def handle(self, cmd: ImportTaskCommand) -> str:
        body = TaskBody(await self._task_loader.load(cmd.md_path))
        name = TaskName(cmd.task_name)
        current_time = self._clock.now()
        
        async with self._uow as uow:
            existing = await uow.tasks.get_current_by_name(name)
            if existing:
                existing.supersede()
                await uow.tasks.save(existing)
                
            task = Task.create(
                id_=self._id_gen.new_task_id(),
                name=name,
                body=body,
                now=current_time,
            )
            await uow.tasks.save(task)
            
            # 1. Zbieramy eventy domenowe (np. TaskCreated) z agregatu
            uow.stage_events(task.pull_events())
            
            # 2. Commit uow zapisuje zadanie ORAZ dodaje wiersz w tabeli outbox_event!
            await uow.commit()

        self._logger.info("Task created and event staged in Outbox", task_id=task.id.value)
        # 3. Zwracamy id, zero powiadamiania innych systemów - handler kończy pracę błyskawicznie.
        return task.id.value

3. Skutki uboczne w testach jednostkowych (Fix)
Ponieważ wyciąłeś publishera z handlerów, testy w tests/unit/application/test_handlers.py przestaną działać, ponieważ weryfikowały wywołania FakeEventPublishera.

Od teraz Twoje testy jednostkowe handlerów komend powinny sprawdzać wyłącznie to, czy zdarzenie zostało poprawnie zebrane przez Unit of Work (bo uow.commit() zajmie się zapisem do outboxa).

Podsumowanie nowego stanu systemu:
Dzięki Twojej decyzji architektura stała się krystalicznie czysta:

API / CLI (np. FastAPI) wysyła komendę do CommandBus.

Handler zmienia stan biznesowy, wrzuca event do UoW i robi commit.

Baza danych zapisuje zmianę stanu + wiersz w outbox_event w jednej, niepodzielnej transakcji SQL. Zwraca kontrolę do API/CLI w ułamku sekundy.

Niezależny, pracujący w tle OutboxRelay (opisany w poprzednim kroku) bierze te zdarzenia z bazy, odtwarza je i wrzuca do EventBus.

EventBus odpala reakcje (np. NodeExecutionWorker wykonuje węzeł grafu).

Wypięcie publishera z handlerów to absolutnie doskonały ruch z punktu widzenia projektowania systemów rozproszonych. Czy chcesz zająć się teraz implementacją klasy mapującej (EventDeserializer), którą wrzucimy do Relay'a, by ten potrafił prawidłowo karmić EventBus odtworzonymi obiektami zdarzeń z tabeli SQL?
